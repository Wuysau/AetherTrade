# 双环境与资源操作规范

## 固定映射

| 环境 | 发布分支 | 用途 | 修改权限 |
| --- | --- | --- | --- |
| DEV | public-snapshot（用户称 public） | 全部 Agent 开发和自动测试唯一运行环境 | 经受控入口操作 |
| TEST | 无活动分支（历史 dev 已归档） | 用户操作和独立验收 | Agent 禁止直接修改数据；部署须用户批准 |

自 2026-11-01 起，public-snapshot 是唯一活动集成线：任务分支从最新 public-snapshot 创建，Integration Manager 串行集成到 public-snapshot。历史本地 dev 已删除并归档为 tag archive/dev-before-delete-20261101；origin/dev 仅作为远端历史保留，不参与新任务、自动测试或清理追溯。TEST 暂无活动分支，不能把归档 dev 当作可部署 TEST。环境发布分支与集成分支职责不同：public-snapshot 更新不得自动部署 TEST。TEST 必须固定已批准的提交和镜像摘要，批准需绑定候选 SHA、迁移与回退说明。DEV 测试可运行任务/集成候选的确切源码快照，不能为此创建第三套环境或自动更新公共服务。禁止隐式交换分支映射。

项目只有 DEV 和 TEST 两套长期环境。两者的数据、数据库身份、凭据、端口、网络、持久卷及部署版本均隔离；测试进程不得获得 TEST 连接能力。两者交易模式均保持 PAPER，TEST 不等于 TESTNET。不得启用 TESTNET/LIVE、访问真实交易账户或自动发起付费模型调用。

## 固定服务与租约

所有 Worktree 复用唯一 DEV 服务。禁止按任务或按测试创建 PostgreSQL 容器、Runner 容器、Compose Project 或独立数据卷。qualify_paper_docker.py 及其他入口必须改为提交受控测试请求，复用固定服务；禁止每轮构建、安装依赖或遗留容器。固定依赖镜像更新由受控维护流程执行。

DEV PostgreSQL 可按测试创建隔离数据库，必要时采用经验证的 Schema 隔离。数据库名称前缀不能单独证明所有权。调度器必须登记环境实例 ID、任务/批次/运行 ID、数据库 OID、创建凭据身份、租约、连接角色、到期时间和资源预算；校验实例身份后才发放短期访问权限。禁止测试代码取得共享集群管理凭据。涉及集群级角色/权限的测试必须串行并登记专属临时角色，不能仅依靠数据库隔离声称安全。

只清理本次运行登记且再次核验所有权的临时数据库、Schema、角色及文件；先确认受管进程和连接已终止。未知归属、身份变化、超时仍有进程、租约状态不明均 BLOCKED，保留证据并限制新准入，不能扩大清理范围。

## 权限与预算

Agent 不持有 Docker daemon/socket/named pipe 权限、TEST 凭据、宿主管理员权限。独立管理身份提供结构化操作白名单，仅允许登记的 DEV 服务健康检查、受限测试执行和本次资源租约管理。禁止任意命令透传、任意挂载、特权容器和测试进程访问 Docker。Python 包装脚本与自愿遵守的锁不是 OS 权限隔离，必须实际配置系统权限并验证拒绝行为。

禁止 Docker 全局清理（包括 system/container/image/volume prune）、全局资源删除、VHDX 操作、Docker 数据盘重置、跨盘迁移、未知资源删除及强制清理。磁盘告警不能解除这些限制。TEST 部署和固定环境恢复不属于 Agent 白名单。

实施时必须配置并持久记录：活跃 Worktree 上限、测试并发/排队上限、CPU/内存/PID/连接数/运行时限、容器数量、临时数据库数量、单次与累计磁盘预算、证据保留预算和告警/拒绝准入阈值。缺失预算配置即 BLOCKED；不得使用无限值或临时放宽阈值。数据库重型测试初始并发为 1，增大前须证明资源与身份隔离。监控固定资源清单、磁盘使用趋势和遗留租约；超过阈值停止新任务，报告具体归属，不自动删未知资源。

当前恢复门槛：环境恢复、资源清单确认、DEV/TEST 隔离和受限调度器就绪前，不运行 Docker 构建或数据库资格测试。只编写代码并运行无需 Docker 的安全测试。
