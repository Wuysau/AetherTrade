# Agent Worktree 与串行集成规范

## 创建与职责

新任务由受管入口从最新已确认的 dev SHA 创建 codex/ 任务分支及独立 Worktree。登记 task_id、batch_id、依赖、负责人、归属、文件范围、基础 SHA、绝对路径、分支、状态和预算。无法核实最新基线或触及活跃上限时 BLOCKED，不静默从其他分支启动。

一任务一写入者。Agent 仅修改其 Worktree、执行任务轻量验证并提交；不得自行合并 dev/main/public-snapshot、部署或启动额外环境。所有 Worktree 共用 DEV 固定服务。历史工作树先盘点、登记并保护未提交/忽略文件，不直接批量删除或把未知任务计为已完成。

Integration Manager 是唯一集成写入者，维护持久队列和跨进程独占锁；提交、任务依赖、待集成 SHA 必须固定。轻量验证通过后入队，串行构造合并候选，必要快速验证通过后以比较原 dev SHA 的方式更新 dev。若 dev 已变化，重新排队，不覆盖并发提交。可使用固定管理 checkout，不能为每项合并创建新运行环境。

冲突进入 BLOCKED 并保留任务目录，由负责者解决后重新提交。快速验证失败保留候选、日志与任务目录，不自动强推、重置用户修改或进行清理。所有任务合并之后才集中完整验收，详见 TEST_SCHEDULING.md。

## 自动清理的全部必要条件

- 任务轻量验证和对应合并快速验证通过，且所有任务代码均提交。
- 任务提交及合并提交可以从 dev 追溯，分支 tips 与登记时一致；不得只凭 cherry-pick 相似性判断可删。
- 必要源码来源和验证证据已归档到工作树外的持久位置，内容/哈希可读且任务登记指向它们；不要求每任务复制整仓或生成巨大 bundle。
- 检查 tracked、untracked、ignored 文件、嵌套仓库/子模块、符号链接/junction，以及所有受管进程和目录占用。忽略文件不等于可丢弃；缓存仅在已登记为可再生且无必要证据/凭据混入时才可受限清理。
- 路径规范化并验证位于登记的任务根目录；目标不是主 checkout、固定环境目录或其他任务。所有权和最终 Git/文件状态必须在删除锁内再次检查，防止检查后变化。

满足全部条件才使用非强制 git worktree remove，随后使用 git branch -d。必须验证物理目录消失、Git 工作树注册消失、对应本地任务分支消失，记录清理收据；仅切分支不算完成。禁止 --force、branch -D、全局 worktree prune 或递归批量删除代替安全门槛。

未保存文件、活跃进程、状态不明、分支未合并、证据未归档、路径不合法、冲突或验证失败均保留目录并记录具体 BLOCKED 原因。不得以用户要求自动整洁为由丢弃数据。删除中断后按原登记 ID 和实际目录/注册/分支状态幂等恢复，不能创建新 ID 掩盖失败。

本地与远程分支分开管理。上述自动回收只针对该任务已合并的本地 codex/ 分支；保护 main、dev、public-snapshot、备份分支、其他任务分支及任何未合并提交。远程分支默认保留，另行授权和核验，不强推。

全量验收不是单个已集成任务的清理前提；必要证据持久保存后可在 MERGED_QUICK_VERIFIED 阶段回收。全量失败通过新修复任务重新创建 Worktree，不依赖旧物理目录存活。当前一次性未跑测试的汇总合并不满足该清理条件。
