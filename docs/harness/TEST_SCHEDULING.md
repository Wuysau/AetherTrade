# 任务轻量验证与集中集成验收

## 分层调度

| 层级 | 发起者 | 范围 | 成功含义 |
| --- | --- | --- | --- |
| TASK_LIGHT | 任务 Agent | 相关单元测试、静态检查、编译验证、必要契约测试 | 任务可提交集成 |
| MERGE_QUICK | Integration Manager | 合并候选 SHA 的最小快速检查和必要契约检查 | 集成及清理门槛之一 |
| TARGETED_INTEGRATION | 统一测试调度器 | 关键依赖节点的最小数据库/生命周期案例 | 仅所测范围验证 |
| BATCH_FULL | 统一测试调度器 | 全部任务集成后的数据库、生命周期、故障注入及既定验收矩阵 | 对确切批次 SHA 的集成验收 |
| REPAIR_TARGETED | 修复任务及调度器 | 只运行失败相关测试，重型部分仍须调度 | 修复范围验证 |
| FINAL_REGRESSION | 统一测试调度器 | 修复全部集成后的最终回归 | 最终验收结果 |

Agent 默认禁止启动 Docker、创建数据库容器或运行完整集成套件。任务提交前按改动范围选取轻量验证；不得将无关全量 pytest、完整数据库资格命令或全前端套件隐藏在构建/验证包装器中。合并后仅执行必要快速验证，不逐任务重复全量验收。

Schema 迁移、资金预留、订单恢复等关键变更，可在依赖节点提交 TARGETED_INTEGRATION 请求，记录必要性、精确案例、依赖 SHA 和预算。由调度器决定准入；依赖必需验证未完成不得声称已满足。禁止自动扩展成完整套件，基础设施未恢复时仍 BLOCKED。

BATCH_FULL 的门槛是冻结任务清单内全部开发任务及依赖均完成、轻量通过并成功集成 dev，且集成快速检查通过。固定任务清单和集成 SHA；验证期间的新提交属于新候选，不能继承旧结果。测试全部复用唯一 DEV 服务，TEST 不承载 Agent 自动化测试。

全量失败后保存失败命令、日志、堆栈、案例 ID、源 SHA 和环境指纹；生成带依赖的具体修复任务和受管 Worktree。修复只跑故障相关测试，经串行集成及快速检查后，由调度器发起最终回归。不得每完成一个修复就自动重跑全套；新增失败按同一流程处理。

## 执行次数与证据

每个请求必须含 task_id/batch_id/run_id、源码 SHA、测试选择、原因、资源预算和幂等键。统一队列维护持久锁及租约，防止多 Agent 重复执行。相同 SHA、环境/依赖指纹和案例选择的已有有效结果可以引用；不得把不同 SHA 的历史结果当成本次结果。自动重试默认 0；重试必须记录故障原因、次数预算和准入决定。超过次数、时长、存储或并发预算则 BLOCKED。

状态必须区分 PASS、FAIL、BLOCKED、NOT_RUN。未运行就是 NOT_RUN；环境不具备运行条件记录 BLOCKED 原因并注明实际测试未执行。退出码非零、缺结果、意外跳过安全案例不能记 PASS。不得通过删除测试、跳过案例、降低风控、缩减能力目录或模拟成交旁路满足验收。

保留命令、开始/结束时间、退出码、测试数量、原始日志、JUnit/结果文件、SHA-256、代码/依赖/环境指纹、执行身份和明确验证范围。凭据不得进入证据。轻量 PASS、MERGE_QUICK PASS、旧提交测试 PASS 都不代表完整集成或交易所资格通过；46 项能力目标、56 项订单验收及原有其他矩阵保持真实状态。

治理实现需有自动化测试覆盖：资源归属/预算、DEV/TEST 隔离、队列重复提交、并发集成、故障恢复、测试分层选择与升级拒绝、临时数据库精确回收、证据状态、Worktree 安全删除。初期用临时 Git 仓库、离线接口替身和无 Docker 测试；真实权限与数据库验证待恢复后单独报告。
