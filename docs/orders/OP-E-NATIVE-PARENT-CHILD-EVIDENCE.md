# Native original and parent-child evidence boundary

Original query inputs come from actual immutable original write/request/binding/
financial records and scoped client registry via read_original_creation, not
from a provider-constructed request or matching hash. A MAY or UNKNOWN source
keeps those exact IDs even after token/proposal expiry. Protected mark and
consumption sources establish historical send context only; they grant no new
permit, ownership or release. Missing consumption must not become a NOT_SENT or
replacement-submission inference.

For native lists, the original request reserves parent and named member client
IDs. A response/query must independently bind the actual parent venue/client ID,
each returned member venue/client ID, product, account, symbol, namespace and
position leg. Missing pending members remain incomplete duties. One parent ACK,
ALL_DONE label or sibling cancel response is not complete fill/account history.

For execution algorithms, creation has only a parent clientAlgoId. Generated
suborders are not preassigned application children; prefix similarity, a DTO
constructor or matching hashes do not establish parenthood. Their actual venue
parent-child graph requires authenticated source records, complete bounded
suborder/query history and original parent identity. Conditional actualOrderId
is an observed child reference, never a second application submission instruction.

V2 query candidates re-read every received raw archive, verify exact hash/path/
scope/request/page/scan metadata, retain fractional JSON numbers as Decimal,
check typed replay, require all original open/history endpoints and contiguous
bounded received pages, reject overlapping/conflicting identities, and never
iterate proportionally to a remote total. A complete NOT_FOUND candidate still
cannot grant retry/release or source authenticity. V1 files/profile/hashes stay
unchanged; V2 is an explicit separate internal contract.

Downstream trusted-source verification must additionally bind each actual node's
admitted quantity/price/fee/gross envelope and complete causal market/session/
trailing/reference graph. Initial-target maximum_order_notional is not an
authorized substitute for a pending node's own admitted envelope. Fill units,
prices, overfills and fees remain raw, with FinancialUnit bridge and retained
discrepancies; candidates cannot be sent into old Spot quantity*price accounting.

Current native transport/source and post-SDK-queue/Linux qualification remain
BLOCKED. All candidate source_verified/ownership/permission/child-send/retry/
release flags remain false. Root owns future authenticated source ingestion,
accounting and distinct management durable V4; creation permits never authorize
management, and no public schema/migration number is assigned in this worktree.
