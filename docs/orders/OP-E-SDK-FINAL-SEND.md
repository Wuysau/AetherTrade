`qualification/nautilus/guarded_target/patch_source.py` rejects any change to both original HTTP source hashes before adding `HttpClient.request_guarded`. The LGPL source and license stay in the complete upstream archive. The tracked diff is `final-send.patch`; the patch is an explicitly separate artifact, never an in-place installed SDK update.

The extension releases the GIL while a current-thread Tokio runtime awaits every real SDK quota on the caller's OS thread. It then reacquires the GIL, checks pending Python signals, and enters the trusted guard context. One real Rust HTTP POST follows; the context exits after HTTP including errors. HTTP/1 only, redirects disabled, retry policy never, no proxies, numeric loopback only. Nested Tokio runtime is rejected. This internal API is not exposed to a model/provider/server request.

The closed `guarded_creation.submit_guarded_creation_probe` accepts only existing engine/write/request/permit/boundary/lease/owner objects. It owns the loopback recorder, fixture key and context callback. It rejects async event-loop use before consumption, because the synchronous owner thread must not silently block cancellation. After one real consumption, the SDK quota wait occurs with no business transaction. Guard entry runs `owner.guard` and `recheck_consumed` against the original MAY/request/permit; no renewal or new ID occurs. The owner RLock remains on its original thread through HTTP; no DB transaction does. Responses remain archived UNKNOWN observations, without fills, cash permissions or native venue qualification. Management permits are not accepted.

The compiled-artifact registry is deliberately empty pending full wheel and real transport/PG measurements. Thus this implementation is currently fail-closed and not an enabled transport. Component tests passing do not qualify the SDK. `probe_transport.py` tests actual quota delay, expiry, current authority mutation, callback failure, missing guard, one-write reset and redirect handling using a real loopback recorder. Original SDK execution produced the expected missing-hook RED.

Build provenance and failures are retained in the guarded_target directory. Recovery: keep existing UNKNOWN command/client IDs and query the original IDs; never replay the uncertain write with a new ID. Reverting this branch disables the candidate while retaining durable MAY/consume evidence. Original Windows SDK installation and old schema hashes require no change. No migration is reserved.

The candidate2 API additionally accepts trusted internal `budget_ms` (1..5000), supplied from the original consumed permit remainder. One absolute Tokio deadline bounds quota waiting and HTTP; deadline expiry before guard entry sends zero requests, while expiry during HTTP remains UNKNOWN with no retry. The guard context is explicitly exited after a normal result or transport/timeout error. This is a synchronous owner-host API, not a general asynchronous Nautilus adapter.
