# PAPER state presentation

The console now separates target quantity, in-flight quantity, actual position,
verified protection and active risk locks. Request receipt status is checked
explicitly; PENDING, SUBMITTED, UNKNOWN and missing status never announce a fill.
Only a reported verified protection state displays a verified quantity. Existing
orders without provenance are labeled historical local simulation records.

This report is presentation evidence, not unified execution qualification.

## Mode configuration followup

AI, RULE and HYBRID retain the existing budget/target/model controls. RULE and
HYBRID additionally accept an explicit PRICE_THRESHOLD rule (LTE/GTE, price,
stop-loss percentage). Activation requires a configured threshold and a
positive stop percentage below 100. RULE confirms PAPER automation with zero
model calls; HYBRID retains model-call cost acknowledgement. Mode changes keep
the strategy in draft until the user explicitly activates it.

Two additional regression tests failed before the controls existed and passed
afterwards. Full frontend checks: typecheck and build exit 0, 105 tests passed.
The RULE form was visually inspected at 390px: 362px dialog, bounded fields,
scrollable content, explicit zero-model-call activation. This proves the UI
request contract, not that a backend accepted/executed a strategy; that requires
the separately integrated runtime and actual database lifecycle tests.
