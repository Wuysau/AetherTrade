## 实施结构

### 官方契约与传输

固定 Demo 域名，沿用 TLS、禁止重定向和代理继承、内存凭据。核对 LIMIT 参数、Decimal filters、签名/时钟、限流及错误分类；尤其 -1007 等执行未知响应必须进入 UNKNOWN 并查询原 ID，不能普通重试。维护官方契约日期和内容摘要；`order/test` 不用于证明成交。

### 部署身份与资格证据

新增可离线验证的部署清单和证据验证器：运行代码内容摘要、依赖/迁移版本、产品、账户 UID/epoch、能力、凭据修订、验证器版本与原始证据哈希均绑定。清单来源必须由运行进程不可写的部署信任配置验证；仅本机 Git SHA 或自行生成哈希不算可信证明。开发者可决定签名格式和模块拆分，但不得将操作者随意提交的路径/JSON变成资格授权。

定义独立受控资格工作流接口，将 PG 检查、连接、下单、撤单、成交和私流恢复各自记录为 PASS/FAIL/BLOCKED/NOT_RUN。资格测试必须有专用的有界授权、最多命令数、金额、时间和原 ID；不能依赖已经取得普通策略资格才能首次验证，也不能授予普通策略执行权。当前阶段只实现流程和离线验证，真实证据保持 NOT_RUN。

### 账户对账与恢复

不假设 Spot REST 与 WS 有共享序列号。将原无条件函数替换为显式、版本化的对账策略接口，策略输入绑定订阅会话、物理 generation、账户及凭据修订、历史基线、订单/成交事实和查询时间范围。单纯空 inbox、相同余额或连续两次相同快照不得构成无缝覆盖证明。

默认拒绝策略保留；候选方案使用专用 Demo 账户、独占发送者、已确认外部活动隔离和有界重叠查询。候选必须明确其一致性假设，未知订单、无法归属成交、外部余额变化、断线和证据过期撤销新风险。若官方接口及实测无法支持批准的假设，记录 BLOCKED，不能靠超时放行。

跨进程恢复授权需要独立可信操作证明旧进程/私流已终止或旧凭据已撤销；随后用新凭据先订阅、按原 ID 补查并核对余额。保留旧 generation、命令、UNKNOWN 和所有历史事实。只有恢复验证器成功才能创建新 generation；不提供通用“清空状态”API。

### AI、订单和停止

沿用 ModelService 的 assessment_v1、模型修订、持久决策抢占、确定性风控、单次 permit、durable MAY、单发送者和成交记账。AI 无权设置能力或 READY；无效输出、过期快照、费用预算耗尽暂停新风险。

为执行窗口加入明确退出预算：到达新开仓截止点后，仅允许已授权的原订单撤销和策略自有头寸减仓。结束必须按已验证订单/成交确认安全状态；未成交、残仓、断线、UNKNOWN 或凭据即将到期返回 NEEDS_OPERATOR，并持久保留保护责任，不宣称完成。凭据过期后没有可保证的自动保护，因此真正启用前仍须验证剩余风险的人工接管程序；不得用定时退出承诺限价平仓一定成功。

界面显示各个阻断原因、证据有效性、授权窗口和停止结果。默认不自动启动；配置、资格测试授权和策略启动互相独立。产品字段、错误码和迁移实现细节由实施者按既有规范决定。

## 验证和交付

### 独立审阅后的实施约定

本阶段须实现可执行的候选验证器与离线端到端路径，不以新增接口加永久拒绝作为完成。候选采用保守账户预算而非声称证明 WS 无缝：专用账户的初始资产和历史边界经独立验收，单一物理 owner 串行发送；每次 ENTRY 前读取签名账户、挂单、原 ID 状态和重叠成交，核对本地账本及修订，未决命令按全额最坏情形保留资金。仅一笔风险增加命令可在途；新的 ENTRY 须等待前单终态及对应成交费用归并。私流用于快速发现冲突，不能提升可用资金；余额增加不能自动提高批准预算。外部活动或任何不一致暂停，所有源的证据使用有界有效期。此策略是待批准和待实测的一致性替代方案，不是 Binance 原生序列屏障；实现不得沿用“已证明无缝覆盖”的旧字段语义。生产仍需绑定该策略版本的真实资格。若现有批准交易契约不允许此替代，保持 BLOCKED 并报告具体冲突，不暗改契约。

信任主体建议为独立部署操作人与受控验收进程：部署操作人固定信任公钥和允许的验证器；验收进程验证原始结果后签发限定能力的证据；恢复操作由操作人授权、恢复验证器核验事实。应用进程不得持有签发私钥或修改信任根。所有证明包含签发者、目的、账户/generation、构建摘要、唯一 nonce、有效期及被替代证明 ID；持久消费与撤销状态防重放，凭据或构建变化使旧证明失效。当前阶段实现验证及离线测试签发器，测试信任根必须显式隔离；正式签发设施缺失时 BLOCKED。

本阶段包含最小人工接管状态机：NEEDS_OPERATOR → TAKEOVER_ACKNOWLEDGED，使用现有认证/CSRF API、当前账户和责任清单摘要、操作人确认和审计记录。确认前先撤销原策略新风险及发送授权，并等待在途工作落定；确认只表示责任已由操作人接受，不表示订单已撤销、仓位已平或交易资格恢复。原策略停止后不能凭此确认重新发送；重新启动必须重新取得所有许可。显示未解决订单、UNKNOWN 和自有持仓，保留全部原始记录。该流程仍须实际验收才可用于运行窗口的风险接管。

本阶段 TASK_LIGHT：纯契约/MockTransport、离线仓库与模型替身、API 授权、针对性前端及类型检查；覆盖重复决策、未知发送、旧 generation、失效证明、无效 AI、限额、部分成交、费用、凭据到期和停止仍有敞口。不得用 mock 资格证明生产执行可用。

独立记录：PostgreSQL 并发/崩溃/权限/迁移 BLOCKED（本阶段未执行），官方 Demo 连接/下单/成交/恢复 NOT_RUN，付费 AI 实测 NOT_RUN。后续获批实测成功才可将相应能力启用。

提交任务分支及轻量证据，由 Integration Manager 串行合入 public-snapshot；本任务不自行合并、部署 TEST 或清理工作树。整体目标只有在真实 Demo 的 AI 决策、风控、发送、成交归并、停止/恢复均验收后才能报告完成。
